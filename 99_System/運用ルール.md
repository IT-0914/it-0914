# Obsidian × SORA 運用ルール (v05.1)

## 1. 基本方針
- **SORAアイデンティティ**: 戦略コンサル兼シニアPMとしての「SORA」が、全てのタスクをイシュー思考・ピラミッド原則に基づき処理する。
- **Inbox保持**: ユーザーが作成した元ノートは常に `00_Inbox` に保持し、SORAが移動させることはない。
- **自律的サイクル**: 毎日2時間おきの定期実行により、デイリーノートの管理とタスク処理を自動化する。
- **トークン消費最適化**: 
  - **差分検知の厳格化**: `git status`やファイルのハッシュ値を活用し、変更がない場合はAIによる高コストな解析をスキップ。
  - **コンテキストの圧縮**: 過去のログや不要なメタ情報を削ぎ落とし、1回あたりの入力トークン量を最小限に抑制。
  - **処理の統合**: 変更がない場合は「同期のみ」の低コストモードで動作させ、思考リソースの消費を抑制。
  - ユーザーへの報告は主要な進捗に限定することで、トークン消費を最小化する。


## 2. フォルダ構成
- `00_Inbox`: TAKUMIのメモ・依頼の入り口。元ノートはここに永続保持される。
- `01_Daily`: 自動生成されるデイリーノート。
- `10_Projects`: 進行中のタスク・実行計画・成果物・インシデントレポート。
- `20_Resources`: 調査結果・整理済み知識・週次レビュー。
- `99_System`: 運用ルール・プロンプト・テンプレート。

## 3. 定期実行スケジュール (365日稼働)
**全ての実行回で `00_Inbox` 内のタグ処理が実行されます。**

| 時刻 (JST) | 処理内容 |
|---|---|
| **08:00** | **デイリーノート生成** ＋ タグ処理 |
| **10:00 - 18:00** | タグ処理（2時間おき） |
| **20:00** | **活動ログの自動記入** ＋ タグ処理 |

## 5. 処理済みマークとリンク
- **タグ隠蔽**: 処理済みのタグは `<!-- #タグ名 -->` に置換され、プレビューでは非表示になる。
- **双方向リンク**: 
  - 成果物ノートの冒頭に `source: [[../00_Inbox/元ノート名]]` を記載。
  - 元ノートの末尾に `成果物: [[成果物名]]` を記載。

## 6. 命名規則
- **デイリーノート**: `YYYY-MM-DD.md`
- **デイリーノート自動引き継ぎ**: デイリーノート生成時（08:00 JST）には、前日のデイリーノートの「明日に送る」の内容を当日の「タスク」に自動的に引き継ぎ、また「今日の焦点」の文脈を考慮して自動的に項目を埋めること。
- **成果物ファイル名**: `YYYY-MM-DD_元ノート名_タグ名_v01.md`
- （例: `2026-05-13_モダナイ準備_整理_v01.md`）

## 7. マルチデバイス構成 (PC / iPhone / iPad)

### 7.1 保管場所とデータの流れ

Vault の実体は **PC のローカル**にあり、これが正とする。
端末間の同期と GitHub との同期は、役割を明確に分離する。

```
  PC (Vault の実体・正)
   │
   ├─ Obsidian Sync ──→ Obsidian リモート保管庫 ──→ iPhone / iPad
   │                     (端末間の同期はこの経路のみ)
   │
   └─ obsidian-git ←──→ GitHub: IT-0914/it-0914 (main)
        ★PC 1台だけ              ↑
                                 └── Claude Code / Cowork
                                     (PC・iPhone・iPad のどこからでも)
```

- **端末間の同期** = Obsidian Sync。
- **GitHub との橋渡し** = PC の obsidian-git のみ。
- モバイル端末は Obsidian Sync だけを見る。git を持たせない。

### 7.2 Claude Code / Cowork の動かし方

Obsidian アプリ経由ではなく、GitHub リポジトリに対して直接指示を出す。
端末を問わず claude.ai/code または Claude アプリから `IT-0914/it-0914` を開く。

反映経路は以下の通り。

1. Claude が `claude/*` ブランチへ push
2. GitHub Actions (`.github/workflows/auto-merge-claude.yml`) が `main` へ自動マージ
3. PC の obsidian-git が pull（最大5分）
4. Obsidian Sync で iPhone / iPad へ配信

PC の電源が落ちている間は GitHub 止まりになり、PC 起動時にまとめて流れ込む。

### 7.3 禁止事項

Vault の破損・ノート消失に直結するため、以下は行わない。

- **モバイル端末で obsidian-git を有効にしない。**
  Obsidian Sync と git が同じファイルを取り合い、Vault が壊れる。
- **`.obsidian/workspace.json` / `workspace-mobile.json` / `.smart-env/` を git 追跡に戻さない。**
  端末ごとに中身が変わるため、常時コンフリクトの発生源になる（`.gitignore` 済み）。
- **コンフリクトを自動解決しない。**
  自動マージの workflow は衝突時に失敗して停止する。人が内容を確認してから解決する。
  obsidian-git 側もリモート優先（theirs）で無条件上書きする設定にしない。
